## 发布定位

2026-10-18 展示曲修订：维护者指出短片段编曲过于简陋后，新增四首独立原创乐谱，主体约 33–42 秒，有旋律发展、和声、段落和收尾；旧入门示例保持不变。展示页、音频清单和发布包改用新曲。新作品逐首渲染并 inspect 通过；修正了写作中发现的宿主 float32 时长少一帧问题，完成两个后端、两种采样率的短音符回归，没有重跑既有完整验收。主观质量留待维护者试听，不能由技术指标代替。

建议把 code-to-music 定位为：**供 coding agent 使用的、以 JSON 乐谱驱动真实音源的离线音乐渲染工具。**

首批用户是希望用代码或 Agent 精确修改器乐、鼓点和短配乐的开发者。核心价值是音符和编曲能版本管理、修改范围可检查、渲染可追溯，以及无 GUI/无音频设备的自动化调用。

首发推荐 Windows x64 的源码预览版，沿用 0.5.x 版本线；准确的首发版本在整理提交和修复后确定。暂不承诺 macOS/Linux、任意 VST3、完整 DAW、实时演奏、自动作曲或人声。已有 12 个固定音源足够支撑首发，当前重点是把安装、许可、演示和证据做实。

## 许可和分发边界

需要分别处理自己的 Python 代码、Python 依赖、外部插件、采样、预设和生成的音乐；一个顶层 LICENSE 不能覆盖全部对象。

| 对象 | 已记录的权利来源 | 首发建议 |
|---|---|---|
| 自有 Python 代码和文档 | MIT，Copyright 2026 Zane-0x5a | 许可和第三方声明随 wheel 提供 |
| Pedalboard | 本机 0.9.26 metadata 和文档标为 GPLv3 | 属于直接软件依赖，明确组合及分发义务；不能因为不提交 DLL 就忽略 |
| Surge XT / FluidSynth | 文档记录 GPL-3.0-or-later / LGPL-2.1-or-later | 保留上游版本、源码及许可入口；首发由安装器从上游获取 |
| sfizioso Player | 文档记录播放器 AGPL-3.0，底层引擎 BSD-2-Clause | 核实具体 VST3 产物的完整许可证与宿主组合关系；不能用引擎的 BSD 标签覆盖播放器，也不能仅凭 worker 隔离就断言没有义务 |
| Salamander / AVL / VSCO | CC-BY-3.0 / CC-BY-SA-3.0 含录制音乐例外 / CC0 | 原始采样再分发与音乐输出分别说明；为示例提供实际使用音源的鸣谢 |
| Surge 厂方预设 | 已记录 Claes 来源和固定指纹；文档引用官方 FAQ 的音频使用说明 | 区分预设文件再分发与渲染音乐的使用权 |
| FFmpeg | 用户自行安装，发行构建可能有不同配置及许可证 | 文档明确外部前置条件；若以后捆绑，单独核对所选构建 |

维护者倾向宽松的 MIT 自有代码许可。MIT 不改变 GPL/AGPL 依赖的许可，不能将整个套件宣传为“全部 MIT、可任意闭源打包”。具体方案及尚待核对的边界见 [LICENSING.md](LICENSING.md)。

首发不自行托管大体积插件、采样或预设包；继续保留上游固定下载、版本与哈希。已增加 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)，分别列出软件与内容权利。音乐输出的授权说明按实际音源逐项写，不作“一切输出都无条件免版税”的统一承诺。

最初普通沙箱无法使用 GitHub 登录态，匿名 API 返回 403；获准访问后已核对两个关键组件的固定版本许可原文，见 LICENSING.md。未来捆绑其他二进制时仍需按实际分发对象核对。

## 执行顺序及完成条件

| 顺序 | 工作 | 完成条件 |
|---|---|---|
| 1：确定首发边界 | Windows x64、源码预览、版权主体及许可方向 | README、LICENSE、包元数据对支持范围和授权表述一致 |
| 2：修正安装承诺 | Python 版本矛盾；源码获取和 FFmpeg 指引；安装失败路径 | 新 checkout + 新虚拟环境按公开步骤可安装；不依赖开发机未声明路径 |
| 3：整理可发布版本 | 整理未提交改动；检查本次包元数据修改；准备人工试听 | 沿用已完成的音源验收，仅按新增改动范围回归；公开摘要说明验收范围 |
| 4：补齐展示和维护 | README、试听、第三方鸣谢、问题模板、贡献说明 | 新用户能理解用途、开始使用、判断限制并反馈问题 |
| 5：建立自动验证 | 先接入 Windows 包与 CLI 检查；音源回归按修改范围执行 | 基础检查不下载音源；需要真实演奏时执行对应回归，不因发版自动重复完整验收 |
| 6：发布 | 审查待发布文件与历史，push，tag，Release | 仓库、tag、安装步骤、音频、证据和 release notes 指向同一版本 |

安装相关改动优先验证受影响路径，例如首次安装、离线缓存、重复安装、PATH 或网络失败；不因公开发布而重新下载全部资源。现有验收已覆盖的路径沿用其结论。安装器通过 VSCO GitHub API 拉取 tree，匿名限流的修复指引仍可继续完善。

CI 先检查普通 wheel 安装、schema 和 CLI；后端、资源或依赖变更再进行相应真实渲染回归。完整 acceptance 按实际需要运行。执行未经信任的外部贡献时，使用隔离的 runner，不在维护者日常工作机上自动运行。

首发暂缓 PyPI 独立安装、一键二进制整包、跨平台与新增音源。特别是 PyPI，需要先提供随包可用的资源安装入口和示例获取方式；否则只解决了库安装，没有交付可用套件。
